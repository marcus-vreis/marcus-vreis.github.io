[`custody-watch`](https://github.com/marcus-vreis/custody-watch) formulates airport luggage theft as an object custody-transfer problem. The pipeline checks whether the person walking away with a bag is the same person who placed it on that ground-plane coordinate. Biometric identification is excluded by design. A pre-commit hook blocks imports of facial recognition libraries (`insightface`, `deepface`, and `dlib`). Because the base rate of actual theft (~1 in 30,000 events) makes binary alarms unusable, the system reduces roughly 600,000 daily events into a ranked review queue of short video clips for human operators.

A geometric boundary splits the codebase in two. Modules left of `GroundPlane` (`VideoSource`, `Detector`, `GroundPlane`) process pixel coordinates; modules to the right (`BagRegistry`, `CustodyFSM`, `PartyManager`, `FlagEngine`, and `AlertQueue`) consume only ground-plane metres and seconds `(x, y, t)`. The state machine is agnostic to whether trajectories originate from camera feeds or 12-line synthetic unit tests. This separation isolated occlusion and ownership bugs where a 5% person-detection miss rate broke 40% of owner links under single-frame assignment.

The evaluation script `evaluate.py` enforces the same check on benchmark protocols. When asked to evaluate the PETS2007 25-second abandonment rule on the [CAVIAR](https://homepages.inf.ed.ac.uk/rbf/CAVIARDATA1/) XML annotations, the script detects that the longest annotated abandonment lasts 13.3 seconds and exits with status code 1, refusing to compute `P_miss` on a time threshold the dataset never reaches.
